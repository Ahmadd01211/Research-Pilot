# Export snapshots and their limits

The export history began with reference CSV and draft Markdown, and now also supports reference XLSX and draft DOCX. Export creation is explicit. The server checks project ownership, rejects an archived project, uses a request UUID for idempotent retries, and stores the exact generated bytes with a SHA-256 hash. A later edit cannot change an earlier download. History lists the latest twenty records per page and each download is owner-scoped.

The CSV uses the standard CSV writer, includes a UTF-8 byte order mark for spreadsheet compatibility, and prefixes cells that could be interpreted as formulas. This changes the display of some legitimate leading symbols, a deliberate tradeoff to reduce spreadsheet formula execution when a researcher opens the file. It contains raw fields, not APA/MLA/Chicago-formatted citations. Markdown preserves plain draft text and citation markers. The draft revision supplied by the UI must still be current when the snapshot is created.

Each file is limited to 2 MB and a project may hold at most 100 MB of export snapshots. The cap protects the database while export retention and purge are designed. History is not a backup, and the current UI cannot remove an old export. Before public release, we need an export retention policy and cleanup path coordinated with project deletion.

To review: open **Exports** from a project, create a reference CSV, download it, then edit a reference and download the historical export again. Its bytes should be unchanged. Save a writing draft and create a Markdown snapshot; if another tab changes that draft before export, the stale request should be rejected.

## Word and Excel snapshots

The same owner-scoped, revision-checked and immutable export path also creates XLSX reference records and DOCX writing drafts. Migration 0015 extends the export-kind constraint. The XLSX workbook has one References sheet, a frozen header and filters. Text cells stay literal strings, including titles beginning with `=`, so they do not become formulas. CSV and XLSX contain raw metadata, not formatted citations.

DOCX preserves the draft title and text in editable paragraphs. Lines beginning with `#` or `##` become headings; other Markdown syntax and citation markers stay literal. It is an editable draft file, not a publication-ready manuscript. Both new formats retain the 2 MB per-file and 100 MB per-project history limits. Export history and downloads preserve the original bytes after later edits. Retention and purge remain release work.

## Literature matrix snapshots - 25 October 2026

Migration 0016 adds matrix_csv and matrix_xlsx to the existing export contract. The exports service calls the matrix module's owner-scoped read service instead of duplicating its persistence rules. Creation holds the project lifecycle lock shared with matrix edits. CSV uses one row per populated field, with row/revision, document, physical page, chunk ID, source hash, reader version and source metadata. Excel adds a comparison sheet and a separate Source provenance sheet. Missing matrix fields remain blank; no findings are generated. All Excel strings are literal cells. Source metadata beyond Excel's cell limit is rejected with a CSV alternative instead of silently truncated. The standard file/project limits, immutable byte history, download ownership and request idempotency apply.

Reference CSV/XLSX also include the new verified volume, issue, pages, article number, publisher and edition fields. Old snapshots keep their original headers and bytes. Migrations are additive and must run before deploying the new API. Migration downgrade can reject retained matrix exports; never delete history just to make a downgrade succeed.
