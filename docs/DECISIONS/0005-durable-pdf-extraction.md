# ADR 0005 — Durable, bounded PDF text extraction

19 October 2026. Builds on ADR 0004; original files remain immutable.

Each new original and its `document_jobs` row commit together. That row is both durable processing state and transactional outbox intent. Migration 0004 backfills jobs for retained originals; removed projects start cancelled. A separate dispatcher publishes queued IDs, then postpones redispatch for 30 seconds. Failed publishing rolls back; queued rows are republished until claimed. Multiple dispatchers use SKIP LOCKED. This is at-least-once dispatch, not exactly-once execution.

Workers atomically claim one queued document, increment attempts, and assign a UUID lease token with a 240-second deadline. Parser wall time is 60 seconds; Celery soft/hard limits are 120/150 seconds. Duplicate messages see processing/terminal state and do nothing. Expired processing leases become queued again up to three total automatic attempts; then they fail visibly. A stale lease/token cannot publish pages. Temporary storage/worker failures get automatic retries; users may request eligible retries up to five total attempts. Deterministic parser failures cannot be retried pointlessly. A duplicate broker delivery can shorten the scheduled retry delay; attempt limits remain authoritative.

Project/job locks are acquired in that order by workers and retry requests. No project transaction is held during parsing. Archive allows an already accepted job to finish, while denying new uploads and manual retries. Removed projects cancel at claim/finalization and never publish new text. Access to retained documents/pages is hidden by project ownership/removal rules. Deferred Trash/purge work must also coordinate queued/inflight work; no deletion policy is introduced here.

pypdf 6.21.1 runs in a Linux subprocess, with no database/Redis environment variables passed, a read-only worker file-volume mount, 512 MiB address-space and 40/45 second CPU limits. The parent imposes 60 seconds wall time. Originals are checksum-verified before parsing. Maximum 300 pages, 100k characters/page and 2m characters/document. At least 40 readable characters are required across the document. Strict PDF parsing can reject files a forgiving viewer accepts; users receive an honest invalid-PDF outcome. Memory/time/page/text limits are operational limits, not guarantees that every scholarly layout will parse correctly.

Subprocess isolation contains normal crashes/resource exhaustion; it is **not a complete hostile-code sandbox**, malware scanner, or network isolation boundary. Stronger process/container isolation and dependency monitoring remain production hardening. Original PDFs remain untrusted attachments. The parser does not render/execute PDF scripts, fetch links, perform OCR or follow embedded documents. SQL parameter values are hidden in API/worker engine exceptions to reduce accidental extracted-text logging.

Successful page rows and the Extracted status commit atomically with one activity entry. Pages have stable (document_id, physical page number) keys; evidence responses include original SHA-256 and extractor version. Extracted text is plain text in the UI, never interpreted as HTML or AI instructions. Empty pages are retained. Extraction may lose tables, formulas, columns, reading order and printed page labels. The UI directs verification against originals. No claim of scientific correctness, OCR, embeddings, RAG readiness or AI-generated analysis is made.

The current source version is an immutable original plus its checksum and extractor identity. Explicit replacement/version-history UI and version-aware retrieval remain future work; changing PDF bytes creates a separate original. No embedding/chunk generation happens in this milestone. A later reprocessing feature must preserve old cited versions rather than silently replace evidence.

Dispatcher health uses a database heartbeat; API readiness checks migration/schema/Redis, not worker availability. Uploads can remain honestly Queued during a processing outage. The worker and dispatcher have separate container health checks. Named volumes and existing account/project data are preserved. Synthetic smoke fixtures are retained for inspection, not mixed with user projects.
